# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.2.0 - 2026-11-11

### Added
- `index_from_storage` configuration option. The sitemap index is rebuilt from the sitemap files found in storage (filtered by the declared process locations) instead of the in-memory state of the run, so it always lists every shard that exists.
  - The index is still written when a process fails, and the other processes keep running. The first error is re-raised afterwards.
  - Numbered parts a successful process no longer writes (e.g. `sitemap3.xml` after a shard shrank to two files) are deleted. Files of failed processes are never touched.
- `Runner#rebuild_index!` rewrites the index from storage without running any process.
- `Adapter#list_sitemaps` for the `:file_system`, `:aws_sdk` and `:noop` adapters.
- `sitemaps.prune_sitemap` event.

### Fixed
- Partial runs preloaded the existing index by fetching `config.url` over HTTP, which failed whenever the stored URL is not publicly routable (e.g. behind the middleware `storage_prefix`) and silently dropped every shard not regenerated by the run. The index is now read through the adapter storage.

## 0.1.2 - 2026-07-17

### Added
- Middleware `aliases:` option: maps an incoming public request path to another public request path (applied before the prefix options), so the same content can be served at multiple locations without a redirect — e.g. `aliases: { "/sitemap.xml" => "/sitemap_index.xml" }`. Accepts a hash or a callable returning a hash.

## 0.1.1 - 2026-05-12

### Fixed
- AwsSdk adapter: switched from the deprecated `Aws::S3::Object#upload_file` to `Aws::S3::TransferManager#upload_file` to silence the deprecation warning and keep working past the next aws-sdk-s3 major.
